# Support

Before opening a request, check the README, `docs/COMPATIBILITY.md`, `references/troubleshooting.md`, and the relevant examples.

## Usage questions

Open a GitHub issue with the `question` label after confirming that the question is not answered in the documentation. Include the repository version, operating system, Python version, agent/runtime (if relevant), exact command, and sanitized output.

## Bugs

Use the **Bug report** issue form. Provide a minimal reproduction and expected versus actual behavior. Remove tokens, passwords, private keys, hostnames, personal data, and other sensitive information before posting logs.

## Feature requests

Use the **Feature request** issue form and describe the problem, intended users, constraints, and alternatives considered.

## Security issues

Do not report vulnerabilities in public issues. Follow `SECURITY.md` and use GitHub's private vulnerability reporting / Security Advisories when enabled for the repository.

Support is provided on a best-effort basis; no response-time or service-level commitment is implied.
