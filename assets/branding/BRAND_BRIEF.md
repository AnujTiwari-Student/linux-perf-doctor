# Branding asset brief — linux-perf-doctor

This is a design brief only. No logo, icon, illustration, screenshot, or banner image is included.

## Product identity

**Project:** `linux-perf-doctor`

**Banner headline:** Linux Performance Diagnostics

**Banner supporting line:** Measure the kernel signals before guessing at the application.

## Suggested palette (not an existing brand system)

Deep navy `#0B1220`, telemetry teal `#21C7B7`, signal ice `#DCE8F2`.

Use the palette as a starting point. Keep accessible contrast and test the mark on both light and dark backgrounds. Coordinate its visual weight with the other four tools so the collection feels related without making the icons interchangeable.

## Symbol direction

A compact kernel/telemetry mark: a clean pulse or signal path passing through a small set of system nodes. Suggests measured diagnostics, not a medical cross or a penguin mascot.

## Logo deliverables to create in your design app

- `logo.svg`: clean vector mark, transparent background, square composition.
- `logo.png`: 512×512 PNG export.
- `logo-dark.svg` and `logo-light.svg`: optional variants for different surfaces.
- A tiny-size check at 32×32 and 64×64 pixels; details that disappear at 32px should be simplified.

## GitHub social-preview banner

- Recommended export: 1280×640 PNG.
- Composition: logo on one side, project name and one-line description on the other, with a restrained technical motif.
- Keep text inside a generous safe area; do not put important copy at the extreme edges.
- Avoid screenshots of real hosts, customer data, credentials, terminal paths, or fake benchmark claims.
- Use the title and supporting line above.

Save the source artwork here if desired as `social-preview.png`, then upload the image separately under **GitHub → Repository → Settings → General → Social preview**. GitHub does not automatically use a file at this path as the repository preview.
